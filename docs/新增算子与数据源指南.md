# 新增算子与数据源指南

- 更新日期：2026-08-19
- 文档类型：How-to Guide。面向后续开发者与 coding agent，给出在项目设计约束内
  添加**新算子**和**新数据源**（单独特征、新宽表、新读取语义）的标准流程。
- 建议先读：[`调用链设计解读_walkthrough.md`](调用链设计解读_walkthrough.md)
  （每步设计意图）、[`调用链_最新.md`](调用链_最新.md)（代码级参考）。
- 每个流程末尾都有 checklist；coding agent 应把 checklist 作为完工标准。

## 0. 先记住的设计约束（不可变条件）

任何改动都不允许违反这些约束；它们是新代码的 review 标准：

1. **计划节点只有三种**：LiteralTerm / SourceTerm / OperatorTerm。新功能
   要么成为算子，要么成为 source，不允许出现第四种 Term。
2. **编译期做全部语义决策**：坐标系、广播合法性、值类型检查、lookback 都必须在
   Compiler 内完成；Runtime 只按计划执行并做契约校验，不做公式或 domain 决策。
3. **物理细节不进入逻辑身份**：表名、字段、reader、load group 只能出现在
   `bind_many()` 之后的对象里；`LogicalPlan.semantic_id` 与 Term 语义键不得
   依赖物理路径。
4. **数组统一 float64、缺失统一 NaN、形状统一 T × N × S**（reduce 结果用
   keepdims 的 singleton 轴，如 T × 1 × S）。
5. **普通算子只有位置语义**：普通算子只按 ArrayLayout 的物理形状（N、S）做
   NumPy 广播，不比较资产类型、代码顺序、frequency 或 calendar；改变 N/S 或
   依赖 Source 元数据的操作必须走显式算子（`resample`/`align_frequency`/
   位置选择/跨轴映射），位置含义由公式作者与数据产品契约保证。详见
   [`数组布局与数据加载边界设计.md`](数组布局与数据加载边界设计.md)。
6. **不修改 `factor_engine/legacy/`**；新核心也不得 import legacy。
7. 改 `data_sources.json` 或 registry 后，必须跑 `uv run pytest` 与
   `uv run ruff check src tests`。

## 1. 新增一个算子

### 1.1 动手前先回答四个问题

| 问题 | 取值 | 决定 |
|---|---|---|
| 输入/输出值类型 | `numeric` / `mask` / `code` | `input_kinds` / `output_kind` |
| 输出形状是否变化 | 不变 / 资产轴 reduce / step 轴 reduce / 其他 | 是否需要专用 `layout_rule` |
| 是否消费日期历史 | 窗口 w / 延迟 p / 无 | `date_lookback` |
| 是不是“坐标变换” | 否 / 是（频率、资产映射、位置选择） | 普通算子 vs 专属 lowering（见 1.7） |

绝大多数新算子落在前三行的常规组合里，按 1.2–1.6 走即可。

### 1.2 第一步：写 kernel

按语义放入对应文件：

```text
operators/elementwise.py    标量/逐元素（add、log、where、mask 逻辑）
operators/timeseries.py     日期轴、step 轴、日内窗口
operators/cross_section.py  截面、分组、成员池
operators/alignment.py      显式坐标映射（lookup_by_col、select_by_pos）
```

kernel 契约（Runtime 按这些假设校验你的返回值）：

- 输入是 float64 的 `T × N × S` 数组（标量参数是 Python 字面量）；
  **返回值 shape 必须精确等于你将声明的 domain 输出**：
  普通算子返回 `T × N × S`；资产 reduce 返回 `T × 1 × S`；step reduce 返回
  `T × N × 1`——reduce 一律 keepdims，不要 squeeze。
- 缺失用 NaN 表达；kernel 不抛“数据缺失”异常，窗口不足就输出 NaN。
- 纯函数：不读写文件、不访问 provider/registry/全局状态；numba、bottleneck
  可以用于性能，但返回必须是 ndarray。
- **kernel 的 Python signature 就是公式参数契约**。Compiler 用
  `inspect.signature(func).bind()` 校验公式调用：公式里写的参数名必须与
  signature 一致；非数据输入的参数必须在编译期是字面量。
- 可选的具名数据输入（如样本掩码）写成带默认值 `None` 的 keyword 参数，
  命名为 `sample_mask` / `weight`，并在注册时通过 `optional_inputs` 声明
  其 ValueKind（参考 `cs_mean(x, sample_mask=None)`）。

模板（日期轴滚动中位数，举例）：

```python
# operators/timeseries.py
def ts_median(x, window=5, min_periods=None, axis=0):
    """沿指定轴计算滚动中位数。"""
    ...  # 输出 shape 与 x 相同，窗口不足处为 NaN
```

### 1.3 第二步：确定 layout rule

layout rule 只做编译期物理形状推导，输入是各输入 Term 的 `ArrayLayout`
（标量为 `None`），输出是输出 ArrayLayout；实现时用 `dataclasses.replace()`
派生，错误用 `DomainError`。普通算子只按 NumPy 广播规则合并 N、S，不比较
资产类型、代码顺序、frequency 或 calendar；布局上的 `asset_type`/`frequency`
是无歧义时传播的溯源提示，只服务 shape 失败诊断与专属 lowering。选择：

| 情况 | 使用的规则 | 注册方式 |
|---|---|---|
| 形状不变（逐元素、时序窗口、transform、截面 transform） | 默认 `broadcast_layout` | `layout_rule` 不传 |
| 资产轴归约成匿名 singleton | `asset_reduce_layout` | 传入 |
| step 轴归约成 singleton | `step_reduce_layout` | 传入 |
| 选择/切片/映射类 | `get_step_layout` / `slice_step_layout` / `select_by_pos_layout` / `lookup_by_col_layout` | 传入 |

只有上表都不适用时才在 `operators/layout_rules.py` 新增规则；新规则必须复用
`_broadcast()` 的广播与提示传播语义，不得在普通算子里恢复业务坐标兼容性检查。

### 1.4 第三步：注册契约

在 `operators/registry.py` 的 `default_operator_registry()` 内注册：

```python
from .timeseries import ts_median

register(
    "ts_median",            # 公式中可见的名称，注册即生效（含 parse 保留名）
    ts_median,              # kernel
    (numeric,),             # 必填数据输入的 ValueKind；可变参用 VariadicInput(kind, min_count)
    numeric,                # 输出 ValueKind；"same" 表示沿用第一个输入
    _date_window_lookback,  # date_lookback：int 常量或 callable(params) -> int
)
```

要点：

- **lookback**：不需要日期历史传 `0`；窗口类复用 `_date_window_lookback`
  （`window-1`，且 `axis != 0` 时为 0）；延迟类参考 `_date_delay_lookback`。
  lookback 返回负数会编译失败；无界历史的算子（无 limit 的 ffill）必须拒绝。
  窗口默认值不是 5 时用 `_window_lookback(default_window)` 生成匹配的回看函数，
  否则省略 window 的调用会算错回看。
- **optional_inputs**：形如 `(("sample_mask", mask), ("weight", numeric))`，
  名字必须与 kernel signature 中的 keyword 参数一致；调用时省略即不参与。
- **可变输入**：`VariadicInput(mask)` 等，配合 kernel 的 `*args`。
- **参数校验**：业务取值范围（如分位数落在 `[0, 1]`、半衰期为正、枚举方法名）
  由算子契约自己校验——在 `registry.py` 写一个 `validate_params(params) -> dict`
  函数（校验并规范化，返回参数副本；非法时抛 `ValueError`），通过 `register(...,
  validate_params=...)` 挂载。Compiler 只做共享结构参数（`window`/`periods`/`axis`
  等）的通用规范化，不感知具体算子的业务语义；不要把算子专属规则写进
  `compiler.py`。参考 `_winsorize_params`、`_quantile_params`、`_top_params`。
- 注册名立即成为公式可见名称与 binding 保留名（不能作为公式局部变量名）。
  命名用小写 snake_case，不要与现有 helper/operator 重名。

### 1.5 第四步：测试

测试放 `tests/`，遵循现有约定：用 `MemoryDataProvider` 构造小数据，经
`FormulaBatch` + `BatchFactorEngine` 走完整链路。至少覆盖四件事：

1. **编译期 Domain / lookback**：`engine.compile(request)`，检查输出 Term 的
   `domain`、`plan.job_lookback`；
2. **数值正确性**：与手工 NumPy 计算逐元素对比（`np.testing.assert_allclose`，
   NaN 位置一致）；
3. **分区一致性**：同一任务用不同 `chunk_size` 结果必须一致（lookback 跨越
   分区边界的场景，参考 `test_chunked_and_whole_domain_results_are_identical_with_lookback`）；
4. **错误路径**：值类型不匹配、非法参数等应在编译期报 `CompileError`/`DomainError`。

```python
def test_ts_median_window_and_lookback() -> None:  # 示例骨架
    provider = MemoryDataProvider(
        dates=DATES, asset_codes={"stk": CODES},
        data={"stk.1d.close": close},
    )
    engine = BatchFactorEngine(provider)
    request = ComputeRequest(
        DomainSpec("20240102", "20240108", {"stk": "all"}, "stk", "1d", 1),
        FormulaBatch.from_text(
            common_inputs='c = source("stk.1d.close")',
            formulas={"f": "factor = ts_median(c, 3)"},
        ),
    )
    job = engine.compile(request)
    assert job.plan.job_lookback == 2
    result = engine.compute(request)
    # np.testing.assert_allclose(result.arrays["f"], expected, equal_nan=True)
```

参考：`tests/test_batch_engine.py`（端到端）、`tests/test_step_reduction_domains.py`
（domain rule）、`tests/test_dynamic_operator_inputs.py`（optional_inputs）。

### 1.6 不要做的事

- 不要把隐式坐标对齐塞进 `_lower()` 或 `broadcast_layout`；改变频率/step
  结构必须是用户显式算子。
- 不要在 kernel 里读配置、读 provider、做日志副作用。
- 不要在普通算子的 layout rule 里比较资产类型、代码顺序、frequency 或
  calendar——普通算子只有位置语义。
- 不要把本该是 source 的东西做成算子（数据加载永远走 DataProvider 三阶段）。

### 1.7 特殊情况：新的“显式坐标变换”

`resample`、`align_frequency`、`__select_asset` 之所以有 Compiler 专属
lowering（`_lower_resample` 等），是因为它们需要在编译期生成 Runtime 参数
（step 索引、目标 pos）。新增此类入口的门槛很高：只有当“编译期必须依据
布局溯源提示推导新的运行时坐标参数”时才考虑，且必须同步：registry 注册
（layout_rule 可为 None）+ Compiler 专属 lowering + 输出边界校验 + 对齐规则文档。
优先评估能否用现有 `select_by_pos` / `lookup_by_col` / `resample` 组合表达。

### 1.8 checklist

```text
[ ] kernel 放入语义正确的文件，纯函数、float64、缺失为 NaN、reduce keepdims
[ ] 返回 shape 与声明的 layout rule 输出精确一致（含 singleton 轴）
[ ] lookback 正确（窗口/延迟随参数变化时必须是 callable，默认值匹配）
[ ] registry 注册完整：input_kinds / output_kind / optional_inputs / layout_rule / validate_params
[ ] 业务参数取值由算子的 validate_params 校验，不写入 compiler.py
[ ] 新增 layout rule 时复用 _broadcast 的广播与提示传播语义
[ ] 测试覆盖 compile layout、数值、分区一致性、错误路径
[ ] uv run pytest 与 uv run ruff check src tests 全绿
[ ] 未修改 legacy/，未让物理细节进入语义身份
```

## 2. 新增一个数据源

### 2.1 先判断属于哪种情况

```text
A. 字段已在某张“会自动扫描”的宽表里（如 SmartQuant.ReturnDaily 新增列）
   -> 零配置，Catalog 自动注册 asset.freq.<列名>；见 2.2
B. 已有物理表上的单个特征（可能带参数，如指数成分/映射字段）
   -> 在 data_sources.json 的 "sources" 加一条记录；见 2.3
C. 新的一张宽表（日期 × 资产 × 字段）
   -> data_sources.json 的 "source_tables" 加记录并声明 reader/query_builder；见 2.4
D. 新的资产类型/资产轴
   -> 资产轴与代码映射登记在 Provider 代码注册表；见 2.5
E. 新的读取语义（报告期、派生字段、映射换算等）
   -> 新增具名 Query Builder 或 Reader；见 2.6
```

逻辑 key 统一是 `asset.freq.name`（`parse_feature_key`；name 部分可含点，
如 `stk.1d.industry_code.SW2021.L1`）。`value_kind` 可选
`numeric`（默认）/ `mask` / `code`，它在编译期参与算子输入类型检查
（例如 `lookup_by_col` 的第二输入必须是 code）。

### 2.2 情况 A：扫描宽表的新列（零配置）

`source_tables` 中没有显式 `fields` 的数据集，Catalog 会在 Provider 构造时
扫描全部字段（SQL 表走 information_schema 列扫描；MinuteParquet 走样例日期
parquet 的字段扫描），自动注册为 `asset.freq.<列名>`。因此：

- 新列**自动可见**，公式直接 `source("stk.1d.NewColumn")`；
- 新列不是 numeric 语义时，在 `catalog.py` 的 `SCANNED_FIELD_KINDS`
  添加 `{"NewColumn": "code" | "mask"}`；
- 不希望暴露的列：在该数据集记录里加 `"exclude_fields": ["Col"]`
  （全局默认排除清单在 `DEFAULT_EXCLUDES`）。

验证：`SmartQuantDataProvider().describe_many([SourceRefExpr.create("stk.1d.NewColumn")])`
应返回预期 `InputSpec`。

### 2.3 情况 B：sources 记录（单特征/带参数字段）

在 `data_sources.json` 的 `"sources"` 加记录：

```json
"stk.1d.my_feature": {
  "asset": "stk",
  "freq": "1d",
  "name": "my_feature",
  "source": "ReturnDaily",
  "table": "SmartQuant.ReturnDaily",
  "reader": "sql_reader",
  "query_builder": "panel_fields",
  "field": "PhysicalColumn",
  "value_kind": "numeric",
  "params": {}
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| key / name | 逻辑 key 与名称；`asset.freq.name` 必须与 key 一致 |
| asset / freq | 资产的资产类型与频率，决定资产轴和 step 数 |
| source | 数据集家族标签（诊断展示用） |
| table | 物理表，供诊断展示与 Reader 使用 |
| reader | 具名 Reader（schema_version 3 起必填），见 `catalog.py` 的 `READER_NAMES` |
| query_builder | 具名 SQL Query Builder；`reader == "sql_reader"` 时必填，其余 reader 不得声明 |
| field | 物理列名（Query Builder 可改写，如基本面用 `column_name` 参数） |
| value_kind | numeric / mask / code |
| params | 原样进入 `SourceSpec.params`；字段级参数（`column_name`/`field`/`constant`/`default`/`projection`）不参与 LoadGroup 拆组 |

约束：`asset.freq` 组合必须能路由到一个已注册的 dataset；参数化特征
（一个逻辑家族多种取法）用 `params` 区分并在语义参数里显式传入
（参考 `index_member_stat` 的 `index_inner_code`），同一 key 多条记录时必须
可用 `data_code` 消歧。常量投影用 `params.constant`（Query Builder 为既有
物理行投影），缺失位置填充用 `params.default`（LoadNormalizer 应用）。

### 2.4 情况 C：新宽表

**标准“日期 × 资产 × 字段”长行宽表只需要配置，不需要新代码**：
`data_sources.json` 的 `"source_tables"` 加记录，声明 `sql_reader` +
`panel_fields`：

```json
{
  "name": "my_table",
  "asset": "stk",
  "freq": "1d",
  "source": "MyQuoteTable",
  "table": "Schema.TableName",
  "reader": "sql_reader",
  "query_builder": "panel_fields",
  "date_col": "DataDate",
  "trading_flag_col": null,
  "code_col": "InnerCode"
}
```

| 字段 | 说明 |
|---|---|
| name | 可选；数据集的可读名字，`SmartQuantDataProvider(include_tables=[...])` 白名单按它过滤 source_tables 条目（同时按逻辑键过滤 `sources` 段，基本面自动注册需显式包含伪名字 `"fundamentals"`） |
| source | 数据集家族标签（诊断展示用） |
| table | 物理表 `Schema.Table` |
| reader / query_builder | 具名 Reader 与 SQL Query Builder（v3 必填） |
| asset_axis | 已废弃；资产轴改由 Provider 代码注册表提供（见 2.5） |
| date_col | 日期列；必须可与 `'YYYYMMDD'` 字符串字面量比较（DATE 或八字符串列） |
| trading_flag_col | 可选；非空时资产轴查询与读取都会加 `= 1` 过滤 |
| code_col | 资产代码列，默认 `InnerCode` |
| code_identity | 代码列值的身份：`inner_code`（默认）或 `secu_code`；为 `secu_code` 时 Reader 经该资产冻结的 code_map 把过滤值翻译为 SecuCode、结果翻译回 InnerCode |
| fields / exclude_fields | 可选；省略 fields 时自动扫描 information_schema |
| date_col_type | 默认 `"date"` |

代码映射按资产登记在 Provider 代码注册表（`_CODE_MAPS`，见 smartquant.py）：
`{"table": "SmartQuant.InnerCode_SecuCode"}` 为静态映射表，
`{"from_asset_axis": true}` 为按日期从资产轴表取（dated 映射）。某资产挂载了
`secu_code` 数据集但注册表未登记其映射时，轴冻结阶段直接报错——映射来源没有
默认推断，必须显式登记。映射在编译期随资产轴冻结（每资产每任务只查一次，
日期范围含 lookback），Reader 从冻结上下文取用。

按日期分区的日频 parquet 面板（每日一个文件、无 step 轴、可以是 SecuCode
代码列）使用 `parquet_panel` reader，配置与分钟 parquet 相同但要求 S=1；
参考内置 `ops_daily` 条目。

`sql_reader` + `panel_fields` 的物理契约（新表必须满足）：

- 按 `(date_col, code_col)` 定位行，`SELECT date_col AS DataDate, code_col AS
  InnerCode, <各字段 AS value_i>` 返回规范 labels 长行；
- 缺失的 (日期, 资产) 组合**不出现在结果里**，LoadNormalizer 散布时自然为
  NaN（或 source 声明的 `default`）；不要自造占位行；
- 日期值经 `normalize_date_key` 规范为 `YYYYMMDD`，读取过滤是字符串
  BETWEEN，因此日期列必须与该字面量兼容；
- 若声明了 `trading_flag_col`，非交易日行会被过滤。

字段注册：不加 `fields` 时 Catalog 自动扫描该表全部列，自动产生
`stk.1d.<列名>` 等逻辑 source；需要定制 kind/排除列同 2.2。

### 2.5 情况 D：新资产类型 / 资产轴

资产轴与代码映射是任务基础设施，不再是可挂载数据源配置：

- 在 Provider 代码注册表（`_ASSET_AXES`，见 smartquant.py）登记新资产的
  轴表参数（table/date_col/code_col/trading_flag_col）。Provider 用
  `SELECT DISTINCT code_col WHERE date BETWEEN ... [AND flag=1]` 冻结该
  资产类型的任务资产轴；轴可用性与 `source_tables` 挂载无关。
- 若新资产有 `secu_code` 数据源，还需在 `_CODE_MAPS` 登记映射来源。
- 登记后新资产类型自动可用于 `DomainSpec.asset_scope`；公式即可
  `target_asset="newtype"` 或声明该类型 source。
- 跨资产投影（如新资产映射到 stk 轴）使用 `lookup_by_col` + code source，
  参考 `cb.1d.underlying_stk` 的实现方式（`CBStockMap`）。

### 2.6 情况 E：新的读取语义（新 Query Builder 或新 Reader）

先判断特殊性在哪一层（设计文档 §4.5）：

- **SQL 需要特殊构造但结果仍是 date + asset + values 规范 labels**：
  在 `query_builders.py` 新增具名 Query Builder，挂入 `SQL_QUERY_BUILDERS`，
  配置用 `reader: sql_reader` + 新 builder。**不要新增 Reader**。
  参考实现：`adjust_factor`（as-of 相关查询）、`untradable`（多列派生 mask）。
- **物理结果布局或坐标解码是新的**（报告期 rank → step、无日期静态关系、
  位置提示流）：在 `readers.py` 新增具名 Reader，挂入 `READER_REGISTRY`，
  并在 `catalog.py` 的 `READER_NAMES` 登记。参考实现：`fundamental`
  （rank/PIT + step 解码）、`cb_stock_map`（static + 任务轴位置投影）、
  `parquet_bars`（flat 位置流）。

Query Builder 契约：

```python
def my_builder(request: ReaderRequest, aliases: Mapping[str, str]) -> tuple[str, tuple[str, ...]]:
    # 只生成 SQL 与物理字段诊断信息；结果必须是规范 labels 布局：
    # DataDate、InnerCode、可选 Step、value_0/value_1/...
    # 不执行查询、不散布数组、不处理 dtype/Infinity/ValueKind/default。
    ...
```

Reader 契约：

```python
def my_reader(request: ReaderRequest) -> Iterator[RawBatch]:
    # request：同一 LoadGroup 的全部 SourceBinding、catalog、后端、任务轴与诊断回调
    # 产出 RawBatch（mode: "labels" / "flat" / "static"；进程内已对齐数组可用
    # "dense"，frame 为 term_id → ndarray），值列按
    # _aliases(bindings)（value_0/value_1/...）命名；
    # 坐标校验、散布、dtype、Infinity、ValueKind、default 全部由
    # LoadNormalizer（normalize.py）完成，Reader 不分配最终数组。
    ...
```

要求：

- 查询经 `measured_query` / `measured_arrow` 执行，自动写入
  `provider_events` 诊断事件；
- 需要任务资产轴做换算时用 `request.axes`（参考 `cb_stock_map`），缺失时抛
  `DataProviderError`；
- 影响物理行集合或坐标解码的共享参数进入 LoadGroup 兼容键；字段级参数
  （`column_name`/`field`/`constant`/`default`/`projection`）不拆组；
- 不提供万能 `custom` Reader、任意 SQL DSL 或插件框架。

再按 2.3 为它写 `sources` 记录（显式声明 `reader` / `query_builder`）。

## 3. 给 coding agent 的工作流建议

1. 先读三份文档：本指南（流程）、`调用链设计解读_walkthrough.md`（设计意图）、
   `调用链_最新.md`（代码细节与字段清单）。领域术语以根目录 `CONTEXT.md` 为准。
2. 算子任务：先明确给出 §1.1 四问的答案再写代码；kernel、registry、测试
   一次提交中完成；提交前跑 `uv run pytest` 和 `uv run ruff check src tests`。
3. 数据源任务：先判定 §2.1 情况；能配置解决的不要写代码，能复用 `_wide`
   的不要写新读取器。改 `data_sources.json` 后必须跑一遍 describe 验证。
4. 不修改 `factor_engine/legacy/`；不给新核心引入 legacy import。
5. 拿不准是否违反设计约束时，对照 §0 的不可变条件逐条自查，并在产出中
   说明每一条是否受影响。
