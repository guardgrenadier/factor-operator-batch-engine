# ADR 0017：失败公式清理全部已提交分区结果

- 状态：已接受
- 日期：2026-07-27

> 范围说明（2026-07-27）：磁盘清理保证适用于计算和 staging 写入阶段。ADR 0024 已决定首版不保证 finalize 逐文件替换过程中发生进程崩溃或 I/O 故障时的自动回滚。

## 背景

ADR 0011 已决定：某个 `formula_id` 的任一必要分区失败，则该公式整体失败；独立公式仍可继续。

ADR 0014 又允许公式输出节点在就绪后独立产生 `OutputChunk` 并进入结果处理。因此，一个公式在后续分区失败前，可能已经有若干分区写入内存装配器或该公式的磁盘工作路径。

ADR 0011 没有决定这些部分结果应回滚、保留还是作为 partial 产物暴露。

## 决策

以 `formula_id` 为结果完整性和清理单位。

某个公式的任一必要分区失败后：

- 该公式已经提交给 `MemoryResultAssembler` 的所有 OutputChunk 全部清理；
- 删除该公式本次任务的整个磁盘工作路径，从而清理此前已经写入的所有 OutputChunk；
- 该公式不出现在 `ComputeResult.arrays` 中；
- 该公式不出现在 `ComputeResult.artifacts` 中；
- 失败信息进入 `ComputeResult.failures`；
- 其他独立公式的结果不受影响。

因此，OutputChunk 被结果组件接收只表示暂存成功，不表示该公式已经最终提交。结果协议必须支持公式级 `abort(formula_id)` 或等价能力。

## 清理语义

- 对内存结果，清理表示移除该公式的装配状态并释放引擎持有的数组引用；不承诺 Python 或操作系统立即归还物理内存。
- 对磁盘结果，清理表示删除该公式本次任务产生的整个工作路径，不发布 partial artifact。
- 覆盖已有正式产物时，旧产物在新公式结果完整成功前不能被破坏；具体替换方式由 ArtifactStore 设计决定。

## 影响

- 磁盘 OutputChunk 到达后立即写入可整体删除的公式工作路径，但不能在单个分块到达时形成不可撤销的完整 artifact。
- 任意无法撤回已消费结果的外部回调不能直接充当这一协议下的结果提交端。
- 结果分块可以尽早消费，但公式成功只能在其全部必要分区完成后确认。
- 清理范围按失败的 formula ID 隔离，不升级为无关公式或整批任务的回滚。

## 本 ADR 不决定

- 成功公式在自身完成后立即 finalize，还是等待整个任务结束再 finalize；
- 暂存目录和原子替换的具体文件布局；
- 进程崩溃后由谁发现和回收遗留暂存数据；
- 任务级基础设施失败是否要求清理已经完整成功的其他公式。
