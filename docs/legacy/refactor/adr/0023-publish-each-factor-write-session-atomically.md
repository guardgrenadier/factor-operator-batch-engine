# ADR 0023：因子写入会话整体原子发布

- 状态：已取代
- 日期：2026-07-27

> 取代说明（2026-07-27）：ADR 0024 采用更简单的“完整写入 staging 后逐日替换正式文件”。计算和 staging 阶段失败仍不影响正式数据，但首版不再保证 finalize 过程中的跨日期原子可见性、崩溃回滚或并发读快照。

## 背景

长期因子数据集会被多个任务持续追加新日期或重算覆盖已有日期。一次公式计算可能涉及多个日期分区，OutputChunk 会在计算过程中逐步写入磁盘。

如果每个日期分区写完后立即替换正式数据，那么后续日期失败时，正式数据集会处于部分新、部分旧的混合状态。要恢复原状还需要逐日备份和回滚。

ADR 0017 已要求公式失败时清理本次任务产生的全部分区结果。对于长期数据集，还需要保证失败不会改变此前已经发布的历史数据。

## 决策

一个 formula ID 对一个 DatasetKey 的一次 Artifact Write Session，是长期数据集更新的原子发布单位。

- OutputChunk 就绪后立即写入本次会话的工作区；
- finalize 前，正式数据集继续完整提供提交前的旧视图；
- 本次所有必要日期分区成功后，一次发布整个写入会话；
- 任一必要分区失败时，删除整个工作区；
- 失败会话新增或覆盖的任何日期都不能进入正式可见视图；
- 失败不能修改或删除提交前已经发布的分区。

该语义同时适用于：

- 只追加新日期；
- 覆盖已有日期；
- 同时包含新增和覆盖日期的区间重算。

## 可见性示例

```text
published view before session
  20260601 -> old
  ...
  20260630 -> old

work session
  20260601 -> new
  ...
  20260620 -> failure

published view after abort
  20260601 -> old
  ...
  20260630 -> old
```

只有会话全部成功后，本次涉及日期的新分区才同时成为正式视图。

## 影响

- 不能通过逐日直接覆盖正式文件来实现写入，否则需要等价的多日期回滚机制。
- ArtifactStore 需要 manifest 切换、generation 引用或其他能够原子替换数据集可见视图的机制。
- 读取方必须基于一个一致的已发布视图读取，不能扫描并混用未提交工作区。
- 旧分区至少要保留到新视图成功发布；发布后的垃圾回收可以延迟执行。

## 本 ADR 不决定

- 使用单 manifest、CURRENT 指针还是目录 generation 实现原子切换；
- 并发写入同一 DatasetKey 时的冲突检测；
- 是否长期保留历史 generation；
- 崩溃恢复和孤儿工作区清理策略；
- 每日分区的具体编码格式。
