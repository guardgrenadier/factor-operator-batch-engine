# ADR 0014：允许独立消费已就绪的公式输出节点

- 状态：已接受
- 日期：2026-07-27

## 背景

任务级 `LogicalPlan` 是一个共享的多输出 DAG。同一个日期分区内，不同公式的输出节点可能在不同时间完成。

ADR 0010 把 `RuntimePartitionResult` 描述为一次携带当前分区全部输出的返回值。这适合表达分区坐标和报告边界，但如果结果处理必须等待分区内所有输出都完成，就会延长已经完成的结果数组的生命周期，也会把分区错误地变成结果交付的原子单位。

另一方面，把任意 DAG 中间节点都暴露给结果层，会泄漏执行计划内部结构，并使结果协议与公共子表达式消除、引用计数和算子调度耦合。

## 决策

结果处理只观察挂有一个或多个 `formula_id` 的输出节点，不观察普通 DAG 中间节点。

当某个公式输出节点的当前分区结果已经就绪时，该结果可以独立形成 `OutputChunk` 并进入结果处理，不需要等待：

- 同一分区内其他公式输出节点完成；
- 其他日期分区完成；
- 整个任务完成。

`OutputChunk` 仍携带 `formula_id`、`partition_id` 和明确的输出 Domain slice。分区继续作为计算、坐标和报告边界，但不是强制的结果交付原子单位。

## 本 ADR 不决定

- RuntimeBackend 通过同步调用、iterator、queue 还是其他机制交付就绪输出；
- 结果层接收数组时采用借用、复制、共享引用还是所有权转移；
- 输出节点同时被下游公式依赖时，底层数组的具体生命周期；
- 背压、并发写入和进程间传输协议；
- 已交付分块在后续分区或任务失败时如何提交、隐藏或清理；
- 内存、磁盘或其他结果目的地的具体接口。

这些属于后续结果生命周期和实现协议设计。本 ADR 只确定结果层必须允许各公式输出独立前进。

## 影响

- ADR 0010 中“Runtime 每次一次性返回当前分区全部输出”不再是强制协议；该部分由本 ADR 取代。
- `RuntimePartitionResult` 可以继续表达分区完成、失败和 `RuntimeReport`，但不能成为阻塞所有公式输出交付的唯一方式；其最终形态仍待设计。
- 普通中间节点仍由 Runtime 按 DAG 依赖和引用计数管理，不进入 ResultWriter、外部回调或最终结果。
- 一个公式输出节点也可能同时是其他公式的上游节点；“结果可消费”不等于已经确定底层数组所有权可以转移。
