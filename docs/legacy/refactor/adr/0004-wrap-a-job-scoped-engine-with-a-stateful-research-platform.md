# ADR 0004：由有状态研究平台包裹任务级计算引擎

- 状态：已接受
- 日期：2026-07-23

## 背景

当前系统以 `FeatureManager` 为主入口，定义注册、alias、依赖递归、数据路由、公式计算和物化共同参与一次调用。这适合早期交互研究，但使无 `FeatureDef` 的公式批任务必须进入研究定义生命周期，也使多进程 worker 难以获得一份完整、显式的任务输入。

## 决策

研究平台是有状态的，负责持有：

- `FeatureDef` 和 alias；
- helper 与研究会话；
- 数据目录和数据路由基础设施的引用；
- 物化定义、结果索引和其他长期状态。

计算引擎是任务级、近似无状态的。一次调用所需信息通过显式任务协议传入；任务结束后不依赖引擎实例保留定义、Router、Store 或 runtime feature。

计算期间允许存在计划、输入绑定、中间数组、任务级缓存、指标和取消状态。这些属于执行上下文，不是跨任务领域状态。

## 影响

- 交互研究入口需要把 `FeatureDef`、alias 和 helper 展开为普通公式批任务。
- 批量计算和自动挖掘可以直接构造同一种任务，无须伪造 `FeatureDef`。
- 跨任务缓存、数据目录和物化存储由外部服务或基础设施组件管理。
- worker 的输入可以是序列化任务、计划分区和显式数据绑定，而不是完整 `FeatureManager` 对象。
- 当前 `Calculator.runtime_features` 等能力需要重新判断：任务内复用可以保留，但不作为引擎实例的长期状态。

## 尚未决定

- 研究平台、批任务服务和执行编排器是否作为独立包。
- 计划缓存由哪个上层组件持有。
- 金融领域对齐语义在核心编译器与研究适配层之间的归属。
