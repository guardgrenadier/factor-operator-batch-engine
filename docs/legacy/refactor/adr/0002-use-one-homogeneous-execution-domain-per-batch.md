# ADR 0002：每个批次使用单一同质计算域

- 状态：已接受
- 日期：2026-07-23

## 背景

交互研究、已知公式批量计算和自动因子挖掘都会事先确定计算区间和资产轴。允许一个批次同时产生不同资产类型或不同频率的输出会显著增加空间推导、调度和结果协议的复杂度，而当前业务不要求这种能力。

## 决策

一个公式批次共享一个显式 `ExecutionDomain`，至少声明：

- 资产类型；
- 输出频率及 step 轴；
- 输出日期区间；
- 资产轴。

需要不同资产类型或输出频率的公式由调用方拆分为不同批次。

每条公式需要任务内唯一的输出 ID，以便关联结果和错误。研究入口可以使用 `FeatureDef.key`；批量计算和自动挖掘入口可以由调用方分配，或由入口适配器生成稳定 ID。业务名称不属于计算内核的必需语义。

## 日期区间语义

批次声明的是输出日期区间。每日增量更新可以表示为单日输出区间，但计划可以根据窗口、delay 等依赖推导更长的输入读取区间。

因此不把“增量更新”等同于 `start=end` 的全部数据读取。

## 影响

- 输出空间不再依赖 `FeatureDef` 提供 asset/freq。
- 无叶子公式也可以由 `ExecutionDomain` 确定输出空间；是否允许此类公式由上层策略决定。
- 核心引擎无需支持同一批次多资产、多输出频率调度。
- 批次拆分属于调用入口或应用编排层职责。
