# core 最终汇报

本文用于汇报从 `factorops/Operators_Hybrid/` 到 `core/` 的重构结果。重点不是逐行说明代码，而是说明：

1. 为什么要重构。
2. 重构后模块如何设计。
3. `core` 如何取数、计算和物化因子。
4. 新增的资产映射、分组统计、频率对齐、高频计算能力如何使用。
5. 后续如何维护。

更详细文档见：

- [用户手册](用户手册.md)
- [设计文档](设计文档.md)
- [调用链_最新](调用链_最新.md)

## 1. 总体结论

旧框架 `Operators_Hybrid` 以 `DataProvider + Calculator + operators/utils` 为主，取数、变量注册、路径扫描、公式解析、数据对齐、资产映射和保存大量耦合在运行状态里。

新 `core` 将主链路拆成可维护的分层：

```text
FeatureManager
  -> Calculator / Planner / Executor
    -> DataRouter
      -> SmartQuantSourceReader
  -> FeatureStore
```

用户侧收敛成一条推荐路径：

```text
定义 FeatureDef
  -> manager.register(...)
  -> manager.materialize(...)
```

所有 source、已物化 feature、运行时中间结果进入计算层后，都统一为：

```text
FeatureArray = T x N x S
date x asset x step
```

这次重构的核心价值是把旧框架中混在一起的五件事拆开：

```text
定义
取数
对齐
计算
存储
```

## 2. 从 Operators_Hybrid 到 core 的变化

| 维度 | Operators_Hybrid | core |
| --- | --- | --- |
| 用户入口 | `DataProvider`、`Calculator.register_var`、`LazyFormula`、路径状态 | `FeatureManager.register(FeatureDef)` + `FeatureManager.materialize(...)` |
| 数据模型 | DataFrame、2D/3D ndarray、xarray、目录文件混用 | 统一 `FeatureArray(T x N x S)` |
| 特征定义 | 变量名、公式、保存参数、路径分散 | `FeatureDef` 统一记录 key、formula、dependencies、mask、delay、steps |
| 取数方式 | 常先下载 raw 或手动读取，再注册变量 | `DataRouter` 按公式依赖临时读取 source，默认不落 raw |
| source 描述 | 命名规则、正则解析、utils SQL 分散 | `SourceSpec` + `data_sources.json` + `sources.py` |
| 资产轴 | 多处处理 `SecuCode/InnerCode` 转换 | Snapshot 固定 `InnerCode` 轴，边界处转换 |
| 存储 | 输出目录、`success.json`、路径扫描发现特征 | `FeatureStore` 管理 `manifest.json`、`axes/`、`features/` |
| 公式执行 | primitive set、变量映射、运行状态耦合 | `FormulaParser -> Planner -> Executor` 分层 |
| 资产映射 | 分散在数据处理函数 | Planner 显式改写，如股票映射到转债正股 |
| 频率对齐 | 多套调用约定 | Planner 集中处理日频、分钟、resample、delay |
| 分组统计 | 多在后处理或专门函数中完成 | `group_*`、`member_*`、行业/指数 helper 进入公式 |
| 高频计算 | 手动读 parquet、转 3D、再计算 | `MinuteParquet` source + step 算子 + chunk 物化 |
| 可维护性 | 新能力容易散落到多个文件 | source、算子、规划、存储各有固定入口 |

## 3. 旧框架痛点

`Operators_Hybrid` 已经具备数据库读取、分钟 parquet 读取、公式计算、算子库和信号评估能力，但主要问题是边界不清：

1. **取数和计算耦合**
   - `DataProvider` 负责建目录、扫描字段、下载数据、对齐数组。
   - `Calculator` 负责扫描已有特征路径、注册变量、维护 primitive set 和执行公式。
   - 因子依赖常常要从运行过程和本地目录反推。

2. **命名规则承担过多语义**
   - 高频、低频、基本面的变量名通过后缀和正则解析。
   - 基本面季度数、列名、data code、复权、停牌等语义散落在名称和读取函数中。

3. **数据空间缺少统一校验**
   - 日期轴、代码轴、step 轴由不同函数生成。
   - `SecuCode/InnerCode` 映射、资产轴变化、频率混用容易产生隐性错位。

4. **本地存储和 source 边界不清**
   - raw/source、用户导入数据、计算结果通过路径体系混合管理。
   - 目录扫描发现特征，缺少统一 metadata 和 snapshot 校验。

5. **新增能力扩展成本高**
   - 新 source、新算子、新频率、新资产映射都容易跨多个状态对象补丁式维护。

## 4. core 模块设计

### 4.1 总体分层

```text
用户层
  FeatureManager / FeatureDef / helper

计算层
  Calculator
    FormulaParser
    Planner
    Executor
    ops

取数层
  DataRouter
    SourceSpec
    data_sources.json
    SmartQuantSourceReader
    align

存储层
  FeatureStore
    Snapshot axes
    Feature metadata
    Materialized arrays
```

### 4.2 核心对象

| 对象 | 职责 |
| --- | --- |
| `FeatureDef` | 特征定义，记录 key、formula、依赖、mask、delay、steps、是否物化 |
| `FeatureManager` | 用户主入口，负责注册、alias、定义保存/加载、递归物化 |
| `Calculator` | 单次公式计算编排，组织 parse、plan、eval、write |
| `FormulaParser` | 把受限字符串公式解析为内部 Expr |
| `Planner` | 做 alias 展开、资产/频率对齐、mask 注入、delay、指数广播 |
| `Executor` | 递归执行表达式，读取叶子，调用 `ops.py` 算子 |
| `DataRouter` | 把 `asset.freq.name` 解析成 `SourceSpec` 并缓存 source 读取 |
| `SmartQuantSourceReader` | 读取 SmartQuant/OceanBase、分钟 parquet、Signal、Fundamental 等 |
| `FeatureStore` | 管理 Snapshot 固定轴、物化写入、加载和 metadata 校验 |
| `ops.py` | 纯数组算子库，不访问 Store、Router 或 source 配置 |

### 4.3 统一 key 和空间

所有 feature/source key 采用：

```text
asset.freq.name
```

例子：

```text
stk.1d.DailyReturn
stk.1min.close_price
stk.15min.close_15m
cb.1d.underlying_ret
idx.1d.DailyReturn
stk.1d.industry_code.SW2021.L1
stk.1d.is_member.CSI300
```

所有数组统一为：

```text
T x N x S
date x asset x step
```

- `T`：Snapshot 固定交易日轴。
- `N`：Snapshot 固定资产 `InnerCode` 轴。
- `S`：step 轴。`1d=1`，`1min=237`，`5min/15min/30min/60min=48/16/8/4`，基本面多季度为 `quarters`。

### 4.4 本地存储

`FeatureStore` 管理：

```text
snapshot/
  manifest.json
  axes/
    dates.npy
    assets/{asset}/inner_codes.npy
    assets/{asset}/code_map.parquet
  features/{asset}/{freq}/{name}/
    metadata.json
    data/{YYYYMMDD}.npy
    code/{YYYYMMDD}.npy
  feature_defs/
```

设计原则：

- Store 只管理固定轴和已物化 feature。
- source 不写 raw 分区，默认计算时临时读取。
- 如果需要保存 source 副本，应注册一个只引用 source 的 `FeatureDef`，物化后作为普通 feature 管理。
- 读取 feature 时校验日期轴、资产轴、step 是否与当前 Snapshot 一致。

## 5. 取数设计

### 5.1 取数优先级

执行公式时，叶子 key 的读取顺序是：

```text
runtime_features
  -> FeatureStore 已物化 feature
  -> DataRouter 外部 source
```

这意味着：

- 同一个 key 如果已经物化，优先读本地 feature。
- 未物化时才走 source 读取。
- 中间 runtime feature 可以在同一次 `materialize(...)` 中复用。

### 5.2 DataRouter source 解析

`DataRouter.resolve_source(key)` 的优先级：

```text
memory_data
  -> register_source(SourceSpec) override
  -> data_sources.json["sources"] 精确配置
  -> data_sources.json["source_tables"] 表级扫描
```

不会只凭裸字段名模糊匹配。

### 5.3 当前支持的 source

| source | 数据来源 | 用途 |
| --- | --- | --- |
| `ReturnDaily` | `SmartQuant.ReturnDaily` | 股票日频字段 |
| `CBReturnDaily` | `SmartQuant.CBReturnDaily` | 转债日频字段 |
| `IndexQuote` | `JYDB.QT_IndexQuote` | 指数日频字段 |
| `MinuteParquet` | 分钟 parquet + DuckDB | 股票/转债分钟数据 |
| `Fundamental` | `SmartQuant.Fundamental_Item{data_code}` | 基本面多季度 |
| `Signal` | `Signal.runner_value_{runner_id}` | 外部信号 |
| `Untradable` | `SmartQuant.Untradable` | 不可交易过滤 |
| `AdjustFactor` | `JYDB.DZ_AdjustingFactor` | 复权因子 |
| `IndexComponentWeight_Choice` | 指数成分权重表 | 指数成员和权重 |
| `CBStockMap` | 转债基础信息 | 转债正股映射 |

### 5.4 data_sources.json 的角色

`core/data_sources.json` 分两类：

1. `source_tables`
   - 用于普通表字段扫描。
   - 如股票日频、转债日频、指数日频、分钟 parquet。

2. `sources`
   - 用于特殊字段和特殊读取逻辑。
   - 如 `stk.1d.adj_factor`、`stk.1d.is_untradable`、`cb.1d.underlying_stk_col`、`stk.1d.is_member.CSI300`。

示例：查询字段是否可解析。

```python
router = manager.data_router

print(router.search("ClosePrice").head())
print(router.resolve_source("stk.1d.DailyReturn"))
print(router.resolve_source("stk.1d.is_member.CSI300"))
```

### 5.5 临时 source 和内存 source

临时覆盖 source：

```python
from core import DataRouter, SourceSpec

router = DataRouter()
router.register_source(
    SourceSpec.from_key(
        "stk.1d.my_signal",
        source="Signal",
        field="runner_value",
        params={"runner_id": 12345},
    )
)
```

测试用内存 source：

```python
import numpy as np

space = store.resolve_space("stk.1d.memory_x")

    "stk.1d.memory_x": np.ones(space.shape),

```

## 6. 如何使用 core

### 6.1 初始化

```python
from core import FeatureManager, FeatureStore

store = FeatureStore("snapshot_2024")
store.init_snapshot(
    start="2024-01-01",
    end="2024-12-31",
    calendar="cn_a_share",
    assets=("stk", "cb", "idx"),
)

manager = FeatureManager(store)
```

### 6.2 日频字段、复权和停牌过滤

```python
from core import get_lf

manager.register(
    get_lf(
        "ClosePrice",
        asset="stk",
        if_adj=True,
        if_sus=True,
        name="close_adj_sus",
        alias="close",
        overwrite=True,
    )
)

close = manager.materialize("close", overwrite=True)
```

`get_lf(if_adj=True, if_sus=True)` 等价于生成：

```text
apply_mask(
  multiply(stk.1d.ClosePrice, stk.1d.adj_factor),
  mask_not(stk.1d.IfSuspended)
)
```

### 6.3 基本面多季度因子

```python
from core import FeatureDef, get_fund

manager.register(
    get_fund(
        "NPParentCompanyOwners",
        column_name="Value",
        quarters=8,
        name="np_parent_8q",
        alias="np_parent_8q",
        overwrite=True,
    )
)

manager.register(
    FeatureDef.from_key(
        "stk.1d.np_parent_stability",
        alias="np_parent_stability",
        formula="divide(step_mean(np_parent_8q), step_std(np_parent_8q))",
        overwrite=True,
    )
)

factor = manager.materialize("np_parent_stability", overwrite=True)
```

基本面 `quarters=8` 的 source 会形成 `T x N x 8`，后续可直接用 step 算子处理。

### 6.4 高频因子：分钟价量相关

```python
from core import FeatureDef, get_hf

manager.register(get_hf("close_price", asset="stk", freq="1min", alias="close_1m", materialize=False))
manager.register(get_hf("volume", asset="stk", freq="1min", alias="volume_1m", materialize=False))

manager.register(
    FeatureDef.from_key(
        "stk.1d.minute_pv_corr",
        alias="minute_pv_corr",
        formula="step_corr(close_1m, volume_1m)",
        overwrite=True,
    )
)

pv_corr = manager.materialize("minute_pv_corr", overwrite=True)
```

`step_corr` 沿日内 step 维计算每只股票每日的分钟价量相关，输出日频单 step。

## 7. 新增能力展示

这一部分是本次重构最值得汇报的能力：资产映射、分组统计、频率对齐都进入了统一公式系统。

### 7.1 频率对齐能力

#### 7.1.1 分钟显式重采样

细分钟到粗分钟要求显式 resample，聚合方式写在公式中，便于 review。当前统一入口位于
新 batch pipeline：

```python
close_15m = resample(
    get_hf("stk", "1min", "close_price"),
    "15min",
    method="last",
)
```

支持聚合：

```text
last, mean, sum, std
```

#### 7.1.2 日频进入分钟频

当输出是分钟频，输入包含日频 feature 时，Planner 默认按 `delay_lf=1` 延迟日频叶子，避免未来函数。

```python
manager.register(get_lf("DailyReturn", alias="ret"))
manager.register(get_hf("close_price", freq="1min", alias="close_1m", materialize=False))

manager.register(
    FeatureDef.from_key(
        "stk.1min.close_plus_prev_ret",
        alias="close_plus_prev_ret",
        formula="close_1m + ret",
        delay_lf=1,
        overwrite=True,
    )
)
```

规划效果：

```text
stk.1d.DailyReturn
  -> delay(periods=1, axis=0)
  -> 按分钟 step 自动广播参与计算
```

#### 7.1.3 高频到日频

高频到日频通过 step 算子显式表达：

```python
manager.register(
    FeatureDef.from_key(
        "stk.1d.intraday_return",
        formula="""
        log(
            divide(
                step_last(stk.1min.close_price),
                step_first(stk.1min.close_price)
            )
        )
        """,
        overwrite=True,
    )
)
```

### 7.2 资产映射能力

#### 7.2.1 股票特征映射到转债空间

当输出是 `cb.*`，公式引用 `stk.*`，Planner 会通过转债正股映射自动改写。

```python
manager.register(get_lf("DailyReturn", asset="stk", alias="stk_ret"))

manager.register(
    FeatureDef.from_key(
        "cb.1d.underlying_ret",
        alias="cb_underlying_ret",
        formula="stk_ret",
        overwrite=True,
    )
)

cb_underlying_ret = manager.materialize("cb_underlying_ret", overwrite=True)
```

规划效果：

```text
lookup_by_col(
  stk.1d.DailyReturn,
  cb.1d.underlying_stk_col
)
```

其中 `cb.1d.underlying_stk_col` 来自 `CBStockMap` source，表示每只转债正股在股票 Snapshot 轴中的列位置。

#### 7.2.2 指数序列广播到股票空间

指数 `idx.*` 不能隐式混入股票或转债空间，必须显式选择指数。

```python
manager.register(
    FeatureDef.from_key(
        "stk.1d.ret_ex_csi300",
        alias="ret_ex_csi300",
        formula="""
        stk.1d.DailyReturn
        - broadcast_index_feature(index="CSI300", feature="idx.1d.DailyReturn")
        """,
        overwrite=True,
    )
)

ret_ex_csi300 = manager.materialize("ret_ex_csi300", overwrite=True)
```

规划效果：

```text
idx.1d.DailyReturn
  -> 按 CSI300 的 InnerCode 定位 idx 轴位置
  -> select_by_pos
  -> broadcast_ts 到 stk 资产数
```

当前 `sources.py::INDEX_INNER_CODES` 中只有 `CSI300=3145` 已确认。新增指数前需要先维护 InnerCode。

### 7.3 分组统计能力

#### 7.3.1 行业分组统计

行业统计通过公式 helper 展开为 `group_*` 算子。

```python
manager.register(get_lf("DailyReturn", alias="ret"))
manager.register(get_lf("FloatMarketCap", alias="float_mcap"))

manager.register(
    FeatureDef.from_key(
        "stk.1d.ret_industry_demean",
        alias="ret_industry_demean",
        formula='industry_demean(ret, system="SW2021", level=1)',
        overwrite=True,
    )
)

industry_factor = manager.materialize("ret_industry_demean", overwrite=True)
```

依赖：

```text
stk.1d.industry_code.SW2021.L1
```

该 source 当前配置为读取 `SmartQuant.ReturnDaily.IndustryCodeNew`。

加权行业均值：

```python
manager.register(
    FeatureDef.from_key(
        "stk.1d.ret_industry_weighted_mean",
        formula="""
        industry_stat(
            ret,
            method="mean",
            system="SW2021",
            level=1,
            weight="stk.1d.FloatMarketCap"
        )
        """,
        overwrite=True,
    )
)
```

底层算子：

```text
group_mean
group_sum
group_std
group_demean
group_zscore
```

#### 7.3.2 指数成分内统计

指数成分统计通过 `index_member_stat(...)` 展开为 `member_*` 算子。

```python
manager.register(
    FeatureDef.from_key(
        "stk.1d.csi300_ret_mean",
        alias="csi300_ret_mean",
        formula="""
        index_member_stat(
            stk.1d.DailyReturn,
            index="CSI300",
            method="mean",
            broadcast=True
        )
        """,
        overwrite=True,
    )
)

csi300_ret_mean = manager.materialize("csi300_ret_mean", overwrite=True)
```

依赖：

```text
stk.1d.is_member.CSI300
stk.1d.index_weight.CSI300  # 加权统计时使用
```

底层算子：

```text
member_mean
member_sum
member_std
member_demean
member_zscore
```

## 8. 综合因子例子：昼夜合成反转

该例子展示高频 source、日频 source、step 选择、rolling、mask 和 chunk 物化共同工作。

```python
import numpy as np
from core import FeatureDef, get_hf, get_lf
from core.schema import get_freq_step_values

pos_1000 = int(np.where(get_freq_step_values("1min") == 1000)[0][0])

manager.register(get_hf("close_price", asset="stk", freq="1min", materialize=False), overwrite=True)
manager.register(get_lf("OpenPrice", name="OpenPrice_Adj_Sus", if_adj=True, if_sus=True), overwrite=True)
manager.register(get_lf("ClosePrice", name="ClosePrice_Adj_Sus", if_adj=True, if_sus=True), overwrite=True)

manager.register(
    FeatureDef.from_key(
        "stk.1d.intra_1000_close_logret",
        formula=f"""
        log(
            step_last(
                divide(
                    stk.1min.close_price,
                    get_step(stk.1min.close_price, step={pos_1000})
                )
            )
        )
        """,
        materialize=False,
    ),
    overwrite=True,
)

manager.register(
    FeatureDef.from_key(
        "stk.1d.intraday_return_20",
        formula="ts_mean(stk.1d.intra_1000_close_logret, window=20, min_periods=20)",
        materialize=False,
    ),
    overwrite=True,
)

manager.register(
    FeatureDef.from_key(
        "stk.1d.overnight_gap",
        formula="""
        abs(
            log(
                divide(
                    stk.1d.OpenPrice_Adj_Sus,
                    delay(stk.1d.ClosePrice_Adj_Sus, periods=1, axis=0)
                )
            )
        )
        """,
        materialize=False,
    ),
    overwrite=True,
)

manager.register(
    FeatureDef.from_key(
        "stk.1d.overnight_gap_20",
        formula="ts_sum(stk.1d.overnight_gap, window=20, min_periods=10)",
        materialize=False,
    ),
    overwrite=True,
)

manager.register(
    FeatureDef.from_key(
        "stk.1d.day_night_reversal",
        formula="""
        -(
            0.6 * stk.1d.intraday_return_20
            + 0.4 * stk.1d.overnight_gap_20
        )
        """,
        output_mask="""
        equal(
            ts_sum(stk.1d.is_untradable, window=20, min_periods=1),
            0
        )
        """,
        overwrite=True,
        metadata={"factor": "day_night_reversal"},
    ),
    overwrite=True,
)

manager.materialize(
    "stk.1d.day_night_reversal",
    overwrite=True,
    chunk_size=20,
    overlap=20,
    return_array=False,
)
```

这个例子体现：

- `MinuteParquet` 临时读取分钟 close。
- `get_step`、`step_last` 把分钟数据压到日频。
- `get_lf(if_adj=True, if_sus=True)` 处理复权和停牌过滤。
- `ts_mean/ts_sum/delay` 表达日频时序逻辑。
- `output_mask` 做最终不可交易过滤。
- `chunk_size/overlap` 支持高频依赖下的大规模物化。

## 9. 维护方法

### 9.1 新增算子

位置：

```text
core/ops.py
```

步骤：

1. 写纯数组函数，不访问 Store/Router/source。
2. 必要时使用 `ensure_3d(...)` 和 `_check_step_compatible(...)`。
3. 注册到 `default_operator_registry()`。
4. 如果支持 `sample_mask` 自动注入，维护 `engine.SAMPLE_AWARE_OPS`。
5. 如果影响 chunk 历史窗口，维护 `engine.infer_date_overlap(...)`。
6. 更新用户手册和汇报文档。

### 9.2 新增 source

位置：

```text
core/data_sources.json
core/sources.py
core/smartquant.py
```

步骤：

1. 普通表字段优先配置到 `source_tables`。
2. 特殊字段或特殊参数配置到 `sources` 精确字典。
3. 新 source 类型在 `SmartQuantSourceReader.read_source(...)` 增加分派。
4. 读取方法返回 `FeatureArray`，优先复用 `align.feature_from_frame(...)` 或 `align.feature_array(...)`。
5. 用 `router.resolve_source(...)`、`router.read(...)` 做 smoke test。

### 9.3 维护指数和行业

指数 InnerCode 维护在：

```text
core/sources.py::INDEX_INNER_CODES
```

新增指数要同步维护：

- `INDEX_INNER_CODES`
- `stk.1d.index_weight.{INDEX}`
- `stk.1d.is_member.{INDEX}`

行业 source 当前示例：

```text
stk.1d.industry_code.SW2021.L1
```

新增行业体系时，应优先在 `data_sources.json["sources"]` 增加明确 key。

### 9.4 新增频率

位置：

```text
core/schema.py
core/sources.py
core/data_sources.json
```

需要同步维护：

- `SUPPORTED_INTRADAY_FREQS`
- `_INTRADAY_MINUTES`
- `get_freq_step_count(...)`
- `get_freq_step_values(...)`
- `get_resample_group_index(...)`
- `get_ffill_step_index(...)`
- `minute_data_type(...)`
- 分钟 parquet 配置

## 10. 当前边界和后续方向

当前已完成：

- `FeatureManager -> Calculator/Planner/Executor -> DataRouter -> SourceReader -> FeatureStore` 主链路。
- Snapshot 固定轴和统一 `FeatureArray`。
- 日频、分钟、基本面、Signal、指数成分、转债映射等 source。
- 公式解析、mask、delay、跨资产映射、指数广播。
- 行业分组统计、指数成分统计。
- 高频 step 算子和 chunk 物化。
- 用户手册、设计文档、完整调用链文档。

当前边界：

- chunk 物化当前只支持 `workers=1`。
- 细分钟到粗分钟要求显式 resample。
- 指数广播依赖 `INDEX_INNER_CODES`，目前只确认 `CSI300`。
- `ops.py` 已覆盖主路径常用算子，但旧 `operators.py` 中部分非主路径数学算子尚未全部迁移。
- `FeatureStore` 不支持隐式扩轴，轴变化需要重建 Snapshot 或显式迁移。

建议后续：

1. 按实际因子迁移需求补齐旧算子。
2. 为核心 source、Planner 对齐、Store 写入补小样本测试。
3. 继续维护指数 InnerCode、行业体系和成分权重 source。
4. 评估 chunk 并行和高频存储优化，但保持现有模块边界。
5. 将常用生产因子沉淀为版本化 `FeatureDef` 定义库。

## 11. 汇报结论

`core` 不是单纯替换 `operators.py`，而是把因子研究和生产链路重新拆成稳定边界：

```text
定义：FeatureDef / FeatureManager
取数：DataRouter / SourceSpec / SmartQuantSourceReader / data_sources.json
对齐：FeatureSpace / align / Planner
计算：Calculator / Executor / ops
存储：FeatureStore / Snapshot / metadata
```

重构后，因子开发从过程式脚本变成声明式定义：

```text
写清楚因子是什么
框架负责取数、对齐、计算、物化和校验
```

尤其新增和收敛了三类关键能力：

- **资产映射**：股票特征可以自动映射到转债正股空间，指数序列可以显式广播到股票空间。
- **分组统计**：行业分组和指数成分池统计进入统一公式系统。
- **频率对齐**：日频、分钟频、高频到日频、分钟重采样都由 Planner 和 step 算子统一表达。

后续开发应围绕这条主链继续演进，避免回到旧框架中依赖路径扫描、变量名反解析和过程式下载的使用方式。
