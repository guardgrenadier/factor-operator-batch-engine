# 频率与第三维对齐规则

- 状态：已确认并同步到正式设计和 batch engine 实现
- 日期：2026-08-06
- 目的：为简化 `Compiler._lower()` 和取消非必要的隐式频率转换提供规则基线
- 权威设计：已同步到 [`FACTOR_ENGINE_DESIGN.md`](../FACTOR_ENGINE_DESIGN.md)

## 1. 领域模型

每个特征必须从两个独立角度描述：

```text
frequency
  数据在日期/日内时间上的采样频率，例如 1d、1min、5min、15min、30min、60min

step_count
  Runtime 数组 T × N × S 的第三维长度 S
```

二者不能互相推导：

- 日频行情通常是 `frequency=1d, step_count=1`；
- 日频基本面可以是 `frequency=1d, step_count=Q`；
- 分钟行情的 `step_count` 表示一个交易日内的 bar 数；
- step selection、step reduction 等 operator 可以改变 `step_count`，但不必改变 `frequency`。

首版不为基本面报告期增加额外的 step 身份类型。基本面输入之间只比较 `step_count`；单季度/累计值、报告期顺序、PIT 版本等业务语义由用户和数据产品契约负责。

## 2. 四类输入域

四类抽象用于选择对齐策略，具体执行仍使用真实 `frequency` 和 `step_count`。

| 类别 | 缩写 | 典型 frequency | 典型 step_count | 含义 |
| --- | --- | --- | --- | --- |
| 日频行情 | DQ | `1d` | `1` | 每个交易日、每个资产一个行情值 |
| 日频基本面 | DF | `1d` | `Q > 1` | 每个交易日可见的多个报告期值 |
| 粗分钟频 | CI | `5min/15min/30min/60min` | 较少 | 较粗粒度的分钟 bar |
| 细分钟频 | FI | `1min`，未来可包括更细数据 | 较多 | 较细粒度的分钟 bar |

采用“粗分钟频/细分钟频”，不再使用容易产生方向歧义的“低分钟频/高分钟频”。同属粗分钟频不表示频率相同，例如 `5min` 和 `15min` 仍需要显式对齐。

## 3. 已确认的总原则

1. SourceTerm 保留 DataProvider 描述的原始 `frequency` 和 `step_count`。
2. Compiler 不根据任务 target 自动执行普通频率转换。
3. 唯一保留的隐式转换是符合 NumPy 规则的 singleton `1 → N` 广播。
4. singleton 广播可以发生在普通 operator 输入之间，也可以发生在最终输出与任务目标之间。
5. singleton 日频行情与日频基本面或分钟频运算时，输出继承非 singleton 一侧的 `frequency` 和 `step_count`。
6. 除 singleton 广播外，改变 frequency 的操作必须由用户公式显式表达。
7. 基本面之间只比较 `step_count`，其余报告期业务语义由用户负责。
8. 粗分钟频到细分钟频首版只支持显式频率对齐，并且只允许 `ffill` 方法。
9. 细分钟频到粗分钟频只通过显式 `resample` 提供统计聚合。
10. 资产类型、资产代码顺序、日历和轴身份仍必须一致，不能退化为只比较 ndarray shape。
11. 多公式输出允许 singleton `1 → N` 广播，最终共享同一个输出 Domain。

“用户负责对齐”表示不兼容输入在编译期失败，用户需要增加显式 `align_frequency`、`resample`、step selection 或 step reduction；不表示 Runtime 忽略 Domain 后直接计算。

## 4. 4 × 4 规则矩阵

矩阵方向为“行是源类别，列是目标类别”。

标记含义：

- `D`：允许直接计算；
- `B`：允许隐式 singleton `1 → N` 广播；
- `E`：必须由用户写出显式转换；
- `X`：不支持一步直接转换，应拆成多个有明确语义的步骤。

| 源 \ 目标 | 日频行情 DQ | 日频基本面 DF | 粗分钟频 CI | 细分钟频 FI |
| --- | --- | --- | --- | --- |
| 日频行情 DQ | `D` 同域直接计算 | `B` singleton 广播到多 step | `B` singleton 广播到粗分钟 step | `B` singleton 广播到细分钟 step |
| 日频基本面 DF | `E` 显式选择或聚合报告期 | `D/B` step 相等或 singleton 广播 | `X` 先降为日频 singleton，再广播 | `X` 先降为日频 singleton，再广播 |
| 粗分钟频 CI | `E` 显式聚合到日频 | `X` 先聚合到日频，再构造多 step | `D/E` 同频直接计算，否则显式转换 | `E` 显式频率对齐，方法为 `ffill` |
| 细分钟频 FI | `E` 显式聚合到日频 | `X` 先聚合到日频，再构造多 step | `E` 显式 `resample` | `D/E` 同频直接计算，否则显式转换 |

## 5. 矩阵规则说明

### 5.1 日频行情 → 日频行情

- `frequency` 均为 `1d`；
- 日期、资产轴和日历必须一致；
- `step_count=1`，可以直接计算；
- 不隐式添加 delay、mask 或其他 PIT 政策。

### 5.2 日频行情 → 日频基本面

允许 NumPy singleton 广播：

```text
T × N × 1
  broadcast
T × N × Q
```

输出为 `frequency=1d, step_count=Q`。引擎只保证数组广播合法，不判断“把当日行情复制到每个报告期位置”是否符合具体公式的业务含义。

### 5.3 日频行情 → 分钟频

允许日频 singleton 广播到目标分钟 step：

```text
1d × 1 step
  broadcast
5min × S steps / 1min × S steps
```

输出继承分钟输入或任务目标的 `frequency` 和 `step_count`。引擎不自动添加 delay，也不判断日频值在当日何时可用。

### 5.4 日频基本面 → 日频行情

多个报告期值不能自动变成 singleton。用户必须显式选择或聚合，例如：

- 选择某个 step；
- 选择最新可见报告期；
- 多期均值、同比、环比或其他计算。

显式处理后的输出为 `frequency=1d, step_count=1`。

### 5.5 日频基本面 → 日频基本面

首版只比较第三维 shape：

- `step_count` 相等时允许直接计算；
- 一侧为 singleton 时允许 `1 → N` 广播；
- 两个不同的非 singleton step 数不兼容。

引擎不比较单季度/累计口径、报告期顺序或其他基本面元数据。

### 5.6 日频基本面 → 分钟频

基本面报告期 step 不能直接解释为日内时间 step，即使两个维度长度偶然相等也不允许一步转换。

用户必须：

1. 先把基本面多 step 显式选择或聚合为日频 singleton；
2. 再利用允许的 singleton `1 → N` 广播进入分钟域。

### 5.7 分钟频 → 日频行情

一个交易日内有多个观测，必须由用户显式选择 reducer，例如：

- `first/last`；
- `sum/mean/std/max/min`；
- 其他业务聚合。

不提供默认 reducer。

### 5.8 分钟频 → 日频基本面

分钟时间轴不能直接变成报告期轴。用户应先把分钟数据显式聚合为日频 singleton；如果之后确实需要与多 step 基本面计算，再通过 singleton 广播完成。

### 5.9 同类分钟频 → 同类分钟频

- 具体 `frequency` 相同，且 `step_count` 相等或一侧为 singleton：按 NumPy 规则计算；
- 具体 `frequency` 不同：必须显式转换；
- 不能因为两个输入同属粗分钟频或细分钟频就认为已经对齐。

### 5.10 粗分钟频 → 细分钟频

首版只支持用户显式调用频率对齐操作，并指定 `method="ffill"`。转换必须根据具体源频率、目标频率和 step 数生成位置映射。

项目现有 `ffill(x, axis=...)` 表示在既有数组轴上填充缺失值，不改变 frequency。粗到细频率对齐不应复用该名称；候选 API 为 `align_frequency(expr, target_freq=..., method="ffill")`。

Compiler 不自动插入 `ffill`，也不替用户决定：

- bar 时间戳表示 start 还是 end；
- 数据可用时点；
- 是否存在 future leak；
- 非完整交易日如何处理。

### 5.11 细分钟频 → 粗分钟频

只通过用户显式调用 `resample` 完成。`resample` 必须声明 reducer，并根据具体频率建立分组。

首版支持哪些 reducer、是否允许 partial group，应由 `resample` operator 自身的参数契约定义；普通 `_lower()` 不参与选择。

## 6. 普通 operator 的 Domain 推导

普通 operator 完成 ValueKind 校验后，按以下顺序推导输出 Domain：

1. 忽略 scalar literal 的 Domain；
2. 校验所有 tensor 输入的资产轴、代码顺序、日历和 axis fingerprint；
3. 如果 tensor 输入 frequency 相同，按 NumPy 规则合并 `step_count`；
4. 如果 frequency 不同，只允许其中一侧是日频行情 singleton；
5. singleton 日频行情广播后，输出继承非 singleton 输入的 frequency 和 step_count；
6. 其他 frequency 组合编译失败，要求用户显式转换。

NumPy step 合并规则为：

```text
S == S  -> S
1 与 S  -> S
S 与 1  -> S
M 与 N  -> 不兼容，其中 M != N 且 M/N 均不为 1
```

这套规则不在普通 operator 前插入转换节点。Runtime 直接使用 NumPy 广播执行 singleton 输入。

## 7. 显式 Domain operator

只有用户公式中的显式 Domain operator 可以改变非 singleton frequency：

```text
align_frequency(expr, target_freq=..., method="ffill")
  粗分钟频 -> 细分钟频

resample(expr, target_freq=..., method=...)
  细分钟频 -> 粗分钟频或日频

step selection / step reduction
  改变 step_count，frequency 保持不变或按 operator 契约明确改变
```

具体 helper 名称可以在实现阶段调整，但显式调用原则不变。

## 8. 输出 Domain 请求

输出请求分别描述 frequency 和第三维长度：

```python
DomainSpec(
    ...,
    target_freq="5min",
    target_step_count=48,
)
```

- `target_freq` 表示输出采样频率；
- `target_step_count` 表示最终数组第三维长度；
- 二者独立，允许表达 `1d + Q steps` 的基本面结果；
- 如果公式最终输出为 singleton，允许在输出边界广播到 `target_step_count`；
- 多公式输出的 step 数相等或满足 singleton 广播时，可以装配到同一个 `ComputeResult`；
- 其他输出 shape 不一致应在编译期失败。

`target_step_count` 为必填参数，而不是容易与 step 标签数组混淆的 `target_step` 或 `steps`。`ResolvedOutputDomain.steps` 根据 frequency 和 step count 生成标准标签或位置标签。

## 9. 对 `_lower()` 的影响

采用上述规则后，主 lowering 收敛为：

```text
LiteralExpr
  -> LiteralTerm

SourceRefExpr
  -> 原始 frequency + step_count
  -> SourceTerm

普通 OperatorExpr
  -> lower inputs
  -> 校验 ValueKind
  -> 校验资产 Domain
  -> 应用普通 NumPy/singleton Domain 规则
  -> OperatorTerm

显式 Domain OperatorExpr
  -> 按 align_frequency/resample/step operator 的显式契约改变 Domain
  -> OperatorTerm
```

普通 `_lower_source()` 不再：

- 根据任务 `target_freq` 自动广播或重采样 Source；
- 自动执行粗分钟频到细分钟频的 ffill；
- 把所有 Source 提前改写成目标频率。

输出边界只保留已确认的 singleton `1 → N` 广播，不执行其他频率转换。

## 10. 实现验收条件

1. 日频 singleton 与日频多 step 输入可以直接广播。
2. 日频 singleton 与分钟输入可以直接广播，输出继承分钟 Domain。
3. 单独的日频 singleton 输出可以广播到请求的分钟 `target_step_count`。
4. 基本面多 step 不能直接转换为日频 singleton 或分钟 step。
5. 基本面之间只按 NumPy step 规则检查，不比较额外报告期元数据。
6. 粗分钟频到细分钟频只有显式 `align_frequency(..., method="ffill")` 可以通过。
7. 细分钟频到粗分钟频或日频只有显式 `resample` 可以通过。
8. 不同具体分钟频率不会被普通 `_lower()` 自动对齐。
9. 多公式输出允许 singleton 广播，其他不一致 shape 在编译期失败。
10. 相同 shape 但资产代码轴不同的输入仍然失败。
11. LogicalPlan 中除 singleton 输出广播外，不出现由 Compiler 猜测产生的频率转换 Term。
12. whole-domain 与任意日期 chunk 的结果一致。
